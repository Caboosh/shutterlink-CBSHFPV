Record control & OSD telemetry for your FPV camera

ShutterLink is a free, open-source alternative to the itsFPV CamLink. An ESP32-C3 bridges your radio switch (or arming state) straight to a DJI Osmo Action or GoPro camera over Bluetooth, and pushes live camera telemetry into the Betaflight OSD.

This repo (CBSHFPV) is Caboosh's fork of rover1312/shutterlink, kept up to date here with additional changes and camera-backend work.

Requires a Betaflight build with Custom Message OSD elements (MSP2_SET_TEXT 0x3007, custom message types 7–10). Betaflight 4.x and 4.5 are not supported. ShutterLink is not affiliated with or endorsed by DJI, GoPro or itsFPV — all protocols are based on public documentation and community reverse-engineering.

What it does

RC-switch record control

Start/stop recording from any AUX channel, read straight from Betaflight via MSP. Channel, threshold and debounce are all configurable — no recompiling.

Record-on-arm

Optional auto-start when the flight controller arms, with an optional stop-on-disarm and grace-period delay. Toggle it from either Web UI.

Live OSD telemetry

Camera status, rec time, battery, link state, FC battery and arm state — assign any of them to all four Betaflight Custom Message slots.

Two camera backends

DJI Osmo Action (DUML over BLE) and GoPro HERO8 through HERO13 (official Open GoPro BLE API), switchable at runtime.

Saved-camera registry

Scan for nearby cameras, Pair & Save the one that's yours (up to 4), and the ESP32 reconnects automatically forever after. Nothing is written to flash without your consent.

Wi-Fi power switch

Assign a spare AUX channel to kill the Web UI hotspot in flight — saves ~60–100 mA while the BLE camera link keeps running.

Web Serial bench console

A GitHub Pages-hosted page that talks straight to the board over USB — no Wi-Fi needed — for bench setup, unrestricted MSP passthrough and a raw serial log.

Built-in Glassmorphism Web UI

Connect to the ESP32's own hotspot and a full dashboard opens automatically — live status, manual REC/STOP, OTA firmware updates, dark & light mode.

…and persistent NVS-backed settings, status-LED link-state patterns, and a modular firmware split cleanly between MSP/FC handling, camera backends, and the two config transports. See the repository structure for the full breakdown.

How it works

A switch flip (or arming the FC) tells the ESP32 to start or stop the camera over Bluetooth; the camera's own telemetry gets pushed back into your OSD.

Up to four independent telemetry strings pushed on change into Betaflight Custom Messages 1–4 via MSP2_SET_TEXT.

Field Web UI

The ESP32 runs a SoftAP (default SSID ShutterLink). Browse to http://192.168.4.1 from any phone or PC.

Bench console

The same configuration surface is reachable over USB from this site — useful on the bench, or through a Betaflight serial passthrough once it's installed in the quad.
